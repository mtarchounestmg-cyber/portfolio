Présentation générale

Contexte. Un restaurant parisien perd des couverts : pas de réservation en ligne, carte PDF illisible sur mobile, zéro présence Google. Objectif : un site qui donne faim et convertit en réservations.

Objectifs. Design appétissant mobile-first · carte administrable · réservation avec créneaux réels · confirmation email/SMS · SEO local (schema.org Restaurant).

🏠 Accueil immersifHero plein écran, spécialités du chef, avis Google, horaires.
🍽️ Carte filtrableEntrées / plats / desserts, filtres régime (veggie), prix, allergènes.
📅 Réservation liveDate + heure + couverts, contrôle capacitaire, confirmation immédiate.
✉️ NotificationsEmail de confirmation + rappel J-1 via PHPMailer et CRON.
⭐ Avis clientsModération back-office, note moyenne en données structurées.
🔍 SEO localBalises sémantiques, JSON-LD Restaurant, sitemap, Core Web Vitals.
~/02-technique.md

Approche technique

Parti pris : PHP templating côté serveur (pas de SPA) pour un SEO maximal et un hébergement mutualisé à 5 €/mois. Le CSS est 100 % maison (variables, grid, clamp) sans framework pour un contrôle pixel-perfect et un bundle < 40 Ko.

Choix Technologie Pourquoi
Rendu PHP inclus + templates HTML servi direct = SEO parfait, pas de JS requis.
Style CSS custom, mobile-first Léger, rapide (Lighthouse 95+), identité unique.
Interactions JS vanilla (filtres, date-picker) Amélioration progressive, fonctionne sans JS.
Données MySQL : dishes, slots, bookings Carte et réservations administrables.
Réservation Transaction + verrou capacitaire Jamais de surréservation : SELECT … FOR UPDATE.
SEO JSON-LD + Open Graph Étoiles Google, partage réseaux soigné.
~/03-logique.md

Logique de développement

  1. Maquette mobile-first. Le menu et le bouton « Réserver » accessibles en < 2 taps. Palette crème/bordeaux/or, typographie serif pour les titres.
  2. Carte en BDD. Table dishes (catégorie, prix, veggie, spicy, dispo du jour). Le chef active/désactive un plat depuis l'admin, le site suit.
  3. Moteur de réservation. Table slots (date, heure, capacité restante). À chaque réservation : transaction, décrémente, INSERT booking + token d'annulation unique.
  4. Anti-surréservation. SELECT remaining FROM slots WHERE … FOR UPDATE : deux clients simultanés ne peuvent pas prendre la dernière table.
  5. Emails + SEO. Confirmation immédiate avec récap + lien d'annulation ; rappel J-1 par CRON ; JSON-LD Restaurant avec horaires et geo.

Extrait — réservation atomique (PHP/PDO)

src/Booking.php
$pdo->beginTransaction();
$slot = $pdo->query("SELECT remaining FROM slots
  WHERE day='2025-06-14' AND hour='20:00' FOR UPDATE")->fetch();
if ($slot['remaining'] < $couverts) { throw new CompletException(); }
$pdo->prepare("UPDATE slots SET remaining = remaining - ?
  WHERE day=? AND hour=?")->execute([$couverts,$day,$hour]);
$token = bin2hex(random_bytes(16)); // lien d'annulation
$pdo->commit();
