~/01-presentation.md

Présentation générale

Contexte. Une petite bibliothèque municipale veut exposer son catalogue à un site web et à une appli mobile. Il faut donc une API unique, documentée et sécurisée, plutôt que deux back-ends séparés.

Objectifs. Endpoints REST prévisibles · auth JWT stateless · validation stricte · erreurs JSON normalisées · documentation testable sans Postman.

🔑 POST /loginÉchange email + mot de passe contre un JWT valide 1 h.
📖 GET /booksListe paginée, recherche ?q=, filtre ?dispo=1.
➕ POST /booksCréation (rôle admin), validation 422 si champs manquants.
📦 POST /loansEmprunt : vérifie la dispo, 409 Conflict si déjà emprunté.
↩️ DELETE /loans/{id}Retour de livre, remet le stock à disponible.
📄 Docs liveChaque endpoint est exécutable depuis la documentation.
~/02-technique.md

Approche technique

Le parti pris : zéro dépendance Composer. Le JWT (header.payload.signature en HMAC-SHA256) est implémenté en ~60 lignes pour maîtriser la sécurité de bout en bout. Le routeur parse REQUEST_METHOD + PATH_INFO et dispatche vers des contrôleurs fins.

Choix Technologie Pourquoi
Style REST + JSON, URLs plurielles (/books) Convention universelle, cacheable, compréhensible.
Auth JWT HS256 maison, Bearer header Stateless : parfait pour web + mobile ; pas de session.
Back PHP 8 natif, routeur custom Léger, déployable sur mutualisé, code lisible.
Données MySQL + PDO préparé Transactions pour emprunt (livre + loan atomiques).
Erreurs JSON { error, code } + HTTP 400/401/404/409/422 Le client sait toujours quoi afficher.
Docs Page HTML + JS (Swagger-like maison) Test live sans outil externe, exemples cURL/JS/PHP.
~/03-logique.md

Logique de développement

  1. Contrat d'API d'abord. J'ai écrit la liste des endpoints + exemples JSON avant de coder, comme un contrat que le front et le mobile partagent.
  2. Routeur minimal. GET /books/12 → BookController::show(12). Méthode + regex d'URL, 404 JSON si aucune route.
  3. Middleware d'auth. Chaque route protégée extrait le Authorization: Bearer …, vérifie la signature HMAC et l'expiration exp.
  4. Emprunt transactionnel. BEGIN; UPDATE books SET dispo=0 WHERE id=? AND dispo=1; INSERT INTO loans…; COMMIT; — si 0 ligne affectée → 409.
  5. Validation stricte. Titre/auteur requis, année 1000–année+1, pagination bornée (max 100). Erreurs 422 avec détail par champ.

Extrait — vérification JWT (PHP, sans librairie)

src/Auth/Jwt.php
public static function verify(string $jwt): ?array {
    [$h, $p, $s] = explode('.', $jwt) + [null,null,null];
    $expect = hash_hmac('sha256', "$h.$p", $_ENV['JWT_SECRET'], true);
    if (!hash_equals($expect, self::b64url_decode($s))) return null;
    $payload = json_decode(self::b64url_decode($p), true);
    return ($payload['exp'] ?? 0) > time() ? $payload : null;
}
