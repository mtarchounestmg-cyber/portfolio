~/01-presentation.md

Présentation générale

Contexte. Les outils de productivité existants sont souvent trop lourds ou payants. TaskFlow répond à un besoin simple : créer, classer et terminer ses tâches rapidement, avec un compte personnel et des rappels automatiques avant les échéances.

Objectifs. Authentification sécurisée · CRUD complet · organisation par catégories et priorités · détection des retards · rappels email · interface rapide sans rechargement.

🔐 AuthentificationInscription / connexion, mots de passe hachés (bcrypt), sessions PHP sécurisées.
✅ CRUD tâchesCréer, modifier, terminer, supprimer. Titre, description, échéance, priorité.
🗂️ CatégoriesTravail, Perso, Urgent… filtrables en un clic depuis la barre latérale.
🔥 Vues intelligentesAujourd'hui, Urgentes, En retard, Terminées — calculées côté serveur.
🔍 Recherche liveFiltrage instantané en JavaScript, sans recharger la page.
📧 Rappels emailScript CRON quotidien : les tâches J-1 et en retard déclenchent un email.
~/02-technique.md

Approche technique

J'ai choisi PHP natif sans framework : volontairement pédagogique, léger à héberger (mutualisé OVH/Hostinger) et suffisant pour un CRUD. Toute la rigueur est mise sur PDO + requêtes préparées, le hachage password_hash() et une séparation stricte des responsabilités.

Choix Technologie Pourquoi
Back-end PHP 8 natif, architecture MVC maison Zéro dépendance, déployable partout, contrôle total du routeur.
Base MySQL 8 (InnoDB) Relationnel parfait pour users → tâches → catégories ; clés étrangères.
Accès données PDO + requêtes préparées Protection native contre les injections SQL.
Auth Sessions PHP + bcrypt Simple, sûr, régénération d'ID à la connexion.
Front JS vanilla + fetch() Pas de build step ; échanges JSON avec l'API interne.
Emails PHPMailer + tâche CRON Rappels J-1 et relances de retard, file simple en BDD.
~/03-logique.md

Logique de développement

  1. Modélisation BDD d'abord. Tables users, categories, tasks avec FK + ON DELETE CASCADE. Un utilisateur ne voit que ses lignes (WHERE user_id = ? systématique).
  2. Authentification. Inscription avec validation (email unique, 8 car. min), password_hash(), login avec password_verify() + session_regenerate_id().
  3. CRUD + API JSON interne. Le front appelle /api/tasks.php?action=list|create|update|delete en fetch ; réponses JSON ; PHP valide chaque entrée.
  4. Vues métier. « Aujourd'hui » compare due_date = CURDATE(), « En retard » due_date < CURDATE() AND done = 0. Compteurs calculés en SQL (COUNT … GROUP BY).
  5. Rappels. Script cron/reminders.php lancé chaque matin : sélectionne les tâches J-1, envoie via PHPMailer, logue en table reminders_log pour éviter les doublons.

Extrait — création sécurisée d'une tâche (PHP/PDO)

src/Models/Task.php
public function create(int $userId, array $d): int {
    $sql = "INSERT INTO tasks (user_id, category_id, title, description,
            priority, due_date) VALUES (?,?,?,?,?,?)";
    $st = $this->pdo->prepare($sql);   // requête préparée = anti-injection
    $st->execute([$userId, $d['cat'], $d['title'],
        $d['desc'] ?? null, $d['prio'], $d['date'] ?: null]);
    return (int) $this->pdo->lastInsertId();
}

Schéma SQL (simplifié)

database.sql
CREATE TABLE tasks (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL, category_id INT NULL,
  title VARCHAR(150) NOT NULL, priority ENUM('basse','moyenne','haute'),
  due_date DATE NULL, done TINYINT(1) DEFAULT 0,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
