Présentation générale

Contexte. Un e-commerçant exporte ses ventes en CSV depuis Shopify mais ne sait pas les lire : milliers de lignes, pas de graphiques. Insight répond : glissez le CSV, le dashboard se construit seul.

Objectifs. Import CSV tolérant (virgule/point-virgule) · KPIs instantanés (CA, commandes, conversion) · 3+ visualisations · rapports filtrables · export des résultats.

📤 Import CSVDrag & drop, détection auto du séparateur, validation ligne par ligne.
📊 KPIs temps réelCA, commandes, visiteurs, conversion — recalculés à chaque import.
📈 3 graphiquesBarres (CA), doughnut (canaux), courbe (trafic) via Chart.js.
🏆 Top périodesClassement auto des meilleurs mois avec barres de progression.
🧾 CommandesTableau récent avec statuts, montants, recherche.
📥 ExportRe-téléchargez les données nettoyées en CSV.
~/02-technique.md

Approche technique

Architecture hybride : Python traite et valide (le langage de la data), JavaScript visualise (le langage du navigateur). En production, un micro-service Python (Flask) expose /api/analyze ; la démo embarque le même parsing en JS pour fonctionner sans serveur.

Choix Technologie Pourquoi
Parsing Python (csv + pandas en prod) Robuste aux fichiers sales : guillemets, encodages, séparateurs.
API Flask → JSON { labels, ventes, visiteurs } Contrat simple ; le front ne connaît que du JSON.
Charts Chart.js (CDN) Responsive, animé, accessible, 3 types en < 30 lignes.
Front JS vanilla + FileReader Import 100 % local : confidentialité, zéro upload.
État store (historique) Retrouve le dernier dataset à la réouverture.
Thème Dark dashboard custom Lisible en réunion, densité d'info élevée.
~/03-logique.md

Logique de développement

  1. Format pivot. Tout dataset devient { labels[], ventes[], visiteurs[] }. Une seule fonction update() redessine KPIs + charts + tops + tableau.
  2. Parsing tolérant. Séparateur [;,], trim, parseFloat() || 0, lignes vides ignorées, dates normalisées. Jamais de crash sur CSV sale.
  3. Calculs dérivés. CA = Σ ventes · commandes ≈ CA/85 € (panier moyen) · conversion = commandes/visiteurs. Recalculés en O(n), instantanés jusqu'à ~50k lignes.
  4. Charts destructibles. Chaque update() détruit les instances Chart.js avant de les recréer — sinon fuites mémoire et superpositions.
  5. Parité Python/JS. Le script Python de prod et le parseur JS de démo partagent les mêmes règles, testés sur le même CSV d'exemple.

Extrait — analyse CSV (Python / prod)

analyzer.py
import csv
def analyze(path):
    labels, ventes, visiteurs = [], [], []
    with open(path, encoding='utf-8-sig') as f:
        for row in csv.DictReader(f):  # gère , ; " auto
            labels.append(row['date'][5:])
            ventes.append(float(row['ventes'] or 0))
            visiteurs.append(int(row['visiteurs'] or 0))
    ca = sum(ventes)
    return {"labels": labels, "ca": ca,
            "commandes": round(ca/85),
            "conversion": round(ca/85/sum(visiteurs)*100, 1)}
